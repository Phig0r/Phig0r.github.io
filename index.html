Private Airdrop

Prove eligibility. Claim to a different wallet.

Demo available · Sepolia

Why it matters

A public reward claim can expose the connection between the wallet that qualified and the address receiving payment.

What I built

Off-chain registration, browser-generated Noir proofs, and relayed ETH claims. Rust/WASM helpers prepare the same hashes and Merkle inputs used by the circuit.

Validation

60 Noir · 6 Rust · 23 Solidity tests

The issuer can still link requests to claims. Duplicate-claim prevention does not establish a unique person.

Test procedure

From the repository root, after installing dependencies and the project toolchains:

pnpm test
cargo test --locked --manifest-path packages/crypto-lib/Cargo.toml
forge test --root packages/contracts

These run the Noir, Rust, and Solidity suites. On Windows, use WSL for Cargo and Foundry. There are no separate automated server or web test suites.

Provenance

Connect product records to authenticator checks.

Demo available · Sepolia

Why it matters

A copied product label can point to a genuine record without proving that the item carrying it is genuine.

What I built

Role-controlled custody, return, and sale workflows with challenge-response signature checks. Six contract facets share state; software keys simulate the proposed PUF authenticator.

Validation

81 contract tests · 85.68% recorded line coverage

The prototype evaluates software behavior, not physical PUF hardware or the authenticity of real products.

Test procedure

From the repository root:

cd smart-contracts
npm ci
npm test
npx hardhat test --coverage

Tests use a local simulated network. They do not test physical PUF hardware or establish that a product is genuine.

Bound Credentials

Issue credentials that stay with their wallet.

Demo available · Sepolia

Why it matters

A transferable token can change hands independently of the qualification it represents. Verifiers also need to identify the issuing institution.

What I built

Non-transferable certificate tokens with public lookup, issuer enrollment, and role-based permissions. Issuer status controls who can create new credentials.

Validation

Tests for issuance, roles, and transfer rejection

Credentials are bound to a wallet, not proof of a unique person. Their accuracy still depends on the issuer.

Test procedure

After installing dependencies and configuring the contract project:

cd smart-contracts
npx hardhat test

Tests cover contract behavior. A wallet-bound credential does not establish a unique person or the truth of an issuer's claims.
